# 送迎表作成アプリ

生活介護の送迎表（1週間分）を、タブレットで指でうごかして作るアプリです。
株式会社障がい者ライフサポート（広島市佐伯区）の送迎表づくりのために作りました。

- 利用者マスタから、その曜日に来る方を**自動で車に割り当て**ます。
- 変えたいところだけ、**指でひっぱって**動かします。
- できたら**保存**すると、GitHub のデータ用リポジトリに残ります。
- **印刷**を押すと、いつも使っている紙のかたち（A4たて1枚・6台×月〜土）で出ます。

## 大事な考えかた

**アプリが壊れても、送迎表は残る。**
データはぜんぶ、人が読める JSON という文字のファイルで GitHub に置いています。
アプリが動かなくなっても、GitHub でそのファイルを開けば、だれがどの車に乗るかは分かります。

そのために、この中には**むずかしい部品をいっさい使っていません**。
HTML・CSS・JavaScript だけです。`npm install` のような準備もいりません。

# 1. まず、自分のパソコンで動かしてみる

## 1-1. 動かす

1. スタートメニューで「PowerShell」と打って、黒い画面（PowerShell）を開きます。
2. 次の2行を、1行ずつコピーして貼りつけ、Enter を押します。

```
cd C:\Users\tanak\Projects\soutai-app
node tools/serve.js
```

3. 「ブラウザで http://localhost:8080 を開いてください」と出ます。
4. ブラウザ（Edge や Chrome）で <http://localhost:8080> を開きます。
5. やめるときは、黒い画面で **Ctrl** と **C** を同時に押します。

> Python が入っているパソコンなら、こちらでも同じことができます。
> ```
> cd C:\Users\tanak\Projects\soutai-app
> python -m http.server 8080
> ```

**注意：ファイルをダブルクリックして開くと動きません。**
`index.html` を直接ダブルクリックすると、ブラウザの決まり（セキュリティ）で中身が読めず、
画面の骨組みだけが出ます。かならず上の方法で `http://localhost:8080` から開いてください。

## 1-2. お試しモード

はじめは「**お試しモード（保存されません）**」と、画面の上にオレンジの札が出ます。
これは、GitHub の鍵（トークン）をまだ入れていない状態です。

- 入っているのは**ぜんぶ架空の名前のダミーデータ**です。本物の利用者は入っていません。
- 保存を押しても、そのパソコンのブラウザの中だけに控えが残り、GitHub には残りません。
- 練習・使い方の説明には、このモードを使ってください。

見本の送迎表が入っています。週送りの ◀ ▶ で **2026年8月3日の週**まで動かすと、
うまった状態の画面と、印刷のかたちが見られます。

# 2. 本番の準備（GitHub）

やることは3つです。**アプリ用**と**データ用**の2つのリポジトリを作り、**鍵（トークン）**を1つ発行します。

| | 名前の例 | 公開／非公開 | 中身 |
|---|---|---|---|
| アプリ用 | `soutai-app` | **public（公開）** | HTML・CSS・JavaScript だけ。**個人情報は入れない** |
| データ用 | `soutai-data` | **private（非公開）** | 利用者・車両・NGペア・週ごとの送迎表 |

なぜ2つに分けるのか：アプリを iPad から URL で開けるようにする（GitHub Pages）には、
アプリ用は公開にする必要があります。利用者のお名前は公開してはいけないので、
データだけを別の非公開リポジトリに置きます。

## 2-1. アプリ用リポジトリを作って、iPad から開けるようにする

1. <https://github.com> にログインします。
2. 右上の「＋」→「New repository」を押します。
3. **Repository name** に `soutai-app` と入れます。
4. **Public** を選びます。
5. 「Create repository」を押します。
6. 次の画面に出る「uploading an existing file」を押し、
   `C:\Users\tanak\Projects\soutai-app` の中身をぜんぶドラッグして入れ、
   下の「Commit changes」を押します。
7. 上の「Settings」→ 左の「Pages」を開きます。
8. **Source** で「Deploy from a branch」、**Branch** で `main` と `/ (root)` を選び、「Save」。
9. 1〜3分待ってページを更新すると、上に URL が出ます。
   `https://（あなたのアカウント名）.github.io/soutai-app/`
10. この URL を iPad の Safari で開き、**共有 → ホーム画面に追加**しておくと、
    アプリのように1タップで開けます。

> iPad の「ファイル」アプリから HTML を開くと、中身が出ません（クイックルックの制限）。
> かならず上の URL から Safari で開いてください。

**このアプリ用リポジトリに入っている `data/` は、ぜんぶ架空の名前の見本です。**
公開されている場所なので、**本物の利用者のお名前は、ぜったいに書きこまないでください。**
本物は、次に作る非公開の `soutai-data` の方に入れます。

## 2-2. データ用リポジトリを作る

1. また「＋」→「New repository」。
2. **Repository name** に `soutai-data`。
3. **Private** を選びます（ここが大事です）。
4. 「Create repository」。
5. `C:\Users\tanak\Projects\soutai-app\data` フォルダを、**フォルダごと**アップロードします。
   （「uploading an existing file」の画面に、`data` フォルダをドラッグします）
6. これで `data/facilities.json` や `data/yahata/users.json` が入った状態になります。
7. 中身のダミーの名前を、本物の利用者に置きかえます。
   直しかたは2つあります。
   - アプリの「マスタ編集」画面で直す（おすすめ）
   - GitHub の画面でファイルを開いて、鉛筆マークから直す

## 2-3. 鍵（アクセストークン）を発行する

1. GitHub の右上の自分のアイコン →「Settings」。
2. 左のいちばん下「**Developer settings**」。
3. 「Personal access tokens」→「**Fine-grained tokens**」→「Generate new token」。
4. 次のように入れます。

| らん | 入れるもの |
|---|---|
| Token name | `送迎表アプリ` |
| Expiration | 90 days（期限。切れたらまた作ります） |
| Repository access | **Only select repositories** → `soutai-data` だけを選ぶ |
| Permissions → Repository permissions → **Contents** | **Read and write** |

**Contents 以外はさわらないでください。** これで「データ用リポジトリのファイルを読み書きする」
だけができる鍵になります。

5. 下の「Generate token」を押します。
6. `github_pat_` で始まる長い文字が出ます。**この文字は1回しか見られません。**
   すぐにコピーしてください。

## 2-4. アプリに鍵を入れる

1. iPad（または送迎表を作るパソコン）で、アプリを開きます。
2. 「設定」を押します。
3. 次を入れて「この端末に保存する」を押します。

| らん | 入れるもの（例） |
|---|---|
| リポジトリ名 | `あなたのアカウント名/soutai-data` |
| ブランチ | `main` |
| アクセストークン | さきほどコピーした `github_pat_...` |
| あなたのお名前 | `田中`（だれが保存したかの記録用） |
| 事業所 | 生活介護 八幡 |

4. 「つながるか試す」を押して、緑の帯で「つながりました」と出るか確かめます。
5. 画面の上の札が「**GitHubに保存します**」に変われば、本番の状態です。

### 鍵のあつかい（かならず守ってください）

- **共用のタブレットには入れないでください。** 送迎表を作る人の端末だけに入れます。
- 他の人に見せない・送らない・写真に撮らない。
- 漏れたかもしれないときは、GitHub の Fine-grained tokens の画面でその鍵を **Revoke（失効）**させ、
  新しく作り直します。アプリの設定で「この端末からトークンを消す」も押してください。
- 期限（Expiration）が切れると保存できなくなります。そのときは新しい鍵を作って、設定に入れなおします。

# 3. 使いかた

1. **週と曜日をえらぶ** … 上の ◀ ▶ で週、その隣で曜日をえらびます。
2. **「自動で割り当て」をおす** … その曜日に来る方が、定員と車椅子スペースを守って車に入ります。
   同じ地区の方はできるだけ同じ車になります。
3. **かえたい人を指でうごかす** … 名前のタイルを、入れたい席へひっぱります。
   - いっしょに乗れない組み合わせのときは、確認が出ます。**禁止はしません**（最後は職員の判断です）。
   - 車椅子スペースがいっぱいの車には入りません。
   - 「まだ乗っていない人」のらんへ戻すと、降ろせます。
   - 時刻は、動かすと先頭から7分きざみで入りなおします。手で直すこともできます。
4. **「送り」タブ** … はじめは「迎え」のコピーが入ります。ちがう人だけ直してください。
   「送り不要」の方は、はじめから入りません。
5. **当日変更** … 名前の右の「当日変更」を押すと、印刷したときその行が**赤字**になります。
6. **この日のメモ** … 画面のいちばん下です。引き継ぎ事項（ピンク）・外部の予定（青）・ふつうのメモを入れます。
   紙のいちばん下のらんに出ます。
7. **「保存」をおす** … GitHub に残ります。押すまでは残りません。
   押していないときは、上に「● まだ保存していません」とオレンジで出ます。
8. **「印刷」をおす** … 紙のかたちの画面になります。「印刷する」でA4たて1枚に出ます。

## だれかと同時に直してしまったとき

このアプリは**1人が編集する**前提です。
それでも、ふたりが同じ週を直して保存すると、あとの人に
「**他の人が先に保存しました。画面を読み直してください**」と出ます。
このときは、先の人の内容が残っています。読み直して、必要なところをもう一度直してください。

# 5. 困ったとき

| こうなった | こうしてください |
|---|---|
| 画面が白いまま／車が出ない | ダブルクリックで開いていないか確認。`http://localhost:8080` から開きます |
| 「お試しモード」から変わらない | 設定でトークンとリポジトリ名の両方が入っているか確認します |
| 「トークンを確認してください」と出る | 期限切れか、権限が足りません。新しい鍵を作り直します（2-3） |
| 「他の人が先に保存しました」と出る | ほかの人が同じ週を保存しています。読み直してから直します |
| 「通信できませんでした」と出る | Wi-Fi につながっているか確認します |
| アプリがどうしても動かない | GitHub の `soutai-data` を開き、`data/事業所/plans/その週.json` を見れば、送迎表の中身は残っています |
