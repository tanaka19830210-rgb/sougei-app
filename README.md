# 送迎表作成アプリ

生活介護の送迎表（1週間分）を、タブレットで指でうごかして作るアプリです。
株式会社障がい者ライフサポート（広島市佐伯区）の送迎表づくりのために作りました。

- 利用者マスタから、その曜日に来る方を**自動で車に割り当て**ます。
- 変えたいところだけ、**指でひっぱって**動かします。
- できたら**保存**すると、GitHub のデータ用リポジトリに残ります。
- **印刷**を押すと、いつも使っている紙のかたち（A4たて1枚・6台×月〜土）で出ます。
- **確定して配信**を押すと、その紙と同じ画像が **LINE WORKS の管理グループのトーク**に届きます。

## 大事な考えかた

**アプリが壊れても、送迎表は残る。**
データはぜんぶ、人が読める JSON という文字のファイルで GitHub に置いています。
アプリが動かなくなっても、GitHub でそのファイルを開けば、だれがどの車に乗るかは分かります。

そのために、この中には**むずかしい部品をいっさい使っていません**。
HTML・CSS・JavaScript だけです。`npm install` のような準備もいりません。

# 1. まず、自分のパソコンで動かしてみる

## 1-1. 動かす

1. スタートメニューで「PowerShell」と打って、黒い画面（PowerShell）を開きます。
2. 次の2行を、1行ずつコピーして貼りつけ、Enter を押します。

```
cd C:\Users\tanak\Projects\soutai-app
node tools/serve.js
```

3. 「ブラウザで http://localhost:8080 を開いてください」と出ます。
4. ブラウザ（Edge や Chrome）で <http://localhost:8080> を開きます。
5. やめるときは、黒い画面で **Ctrl** と **C** を同時に押します。

> Python が入っているパソコンなら、こちらでも同じことができます。
> ```
> cd C:\Users\tanak\Projects\soutai-app
> python -m http.server 8080
> ```

**注意：ファイルをダブルクリックして開くと動きません。**
`index.html` を直接ダブルクリックすると、ブラウザの決まり（セキュリティ）で中身が読めず、
画面の骨組みだけが出ます。かならず上の方法で `http://localhost:8080` から開いてください。

## 1-2. お試しモード

はじめは「**お試しモード（保存されません）**」と、画面の上にオレンジの札が出ます。
これは、GitHub の鍵（トークン）をまだ入れていない状態です。

- 入っているのは**ぜんぶ架空の名前のダミーデータ**です。本物の利用者は入っていません。
- 保存を押しても、そのパソコンのブラウザの中だけに控えが残り、GitHub には残りません。
- 練習・使い方の説明には、このモードを使ってください。

見本の送迎表が入っています。週送りの ◀ ▶ で **2026年8月3日の週**まで動かすと、
うまった状態の画面と、印刷のかたちが見られます。

# 2. 本番の準備（GitHub）

やることは3つです。**アプリ用**と**データ用**の2つのリポジトリを作り、**鍵（トークン）**を1つ発行します。

| | 名前の例 | 公開／非公開 | 中身 |
|---|---|---|---|
| アプリ用 | `soutai-app` | **public（公開）** | HTML・CSS・JavaScript だけ。**個人情報は入れない** |
| データ用 | `soutai-data` | **private（非公開）** | 利用者・車両・NGペア・週ごとの送迎表 |

なぜ2つに分けるのか：アプリを iPad から URL で開けるようにする（GitHub Pages）には、
アプリ用は公開にする必要があります。利用者のお名前は公開してはいけないので、
データだけを別の非公開リポジトリに置きます。

## 2-1. アプリ用リポジトリを作って、iPad から開けるようにする

1. <https://github.com> にログインします。
2. 右上の「＋」→「New repository」を押します。
3. **Repository name** に `soutai-app` と入れます。
4. **Public** を選びます。
5. 「Create repository」を押します。
6. 次の画面に出る「uploading an existing file」を押し、
   `C:\Users\tanak\Projects\soutai-app` の中身をぜんぶドラッグして入れ、
   下の「Commit changes」を押します。
7. 上の「Settings」→ 左の「Pages」を開きます。
8. **Source** で「Deploy from a branch」、**Branch** で `main` と `/ (root)` を選び、「Save」。
9. 1〜3分待ってページを更新すると、上に URL が出ます。
   `https://（あなたのアカウント名）.github.io/soutai-app/`
10. この URL を iPad の Safari で開き、**共有 → ホーム画面に追加**しておくと、
    アプリのように1タップで開けます。

> iPad の「ファイル」アプリから HTML を開くと、中身が出ません（クイックルックの制限）。
> かならず上の URL から Safari で開いてください。

**このアプリ用リポジトリに入っている `data/` は、ぜんぶ架空の名前の見本です。**
公開されている場所なので、**本物の利用者のお名前は、ぜったいに書きこまないでください。**
本物は、次に作る非公開の `soutai-data` の方に入れます。

## 2-2. データ用リポジトリを作る

1. また「＋」→「New repository」。
2. **Repository name** に `soutai-data`。
3. **Private** を選びます（ここが大事です）。
4. 「Create repository」。
5. `C:\Users\tanak\Projects\soutai-app\data` フォルダを、**フォルダごと**アップロードします。
   （「uploading an existing file」の画面に、`data` フォルダをドラッグします）
6. これで `data/facilities.json` や `data/yahata/users.json` が入った状態になります。
7. 中身のダミーの名前を、本物の利用者に置きかえます。
   直しかたは2つあります。
   - アプリの「マスタ編集」画面で直す（おすすめ）
   - GitHub の画面でファイルを開いて、鉛筆マークから直す

## 2-3. 鍵（アクセストークン）を発行する

1. GitHub の右上の自分のアイコン →「Settings」。
2. 左のいちばん下「**Developer settings**」。
3. 「Personal access tokens」→「**Fine-grained tokens**」→「Generate new token」。
4. 次のように入れます。

| らん | 入れるもの |
|---|---|
| Token name | `送迎表アプリ` |
| Expiration | 90 days（期限。切れたらまた作ります） |
| Repository access | **Only select repositories** → `soutai-data` だけを選ぶ |
| Permissions → Repository permissions → **Contents** | **Read and write** |

**Contents 以外はさわらないでください。** これで「データ用リポジトリのファイルを読み書きする」
だけができる鍵になります。

5. 下の「Generate token」を押します。
6. `github_pat_` で始まる長い文字が出ます。**この文字は1回しか見られません。**
   すぐにコピーしてください。

## 2-4. アプリに鍵を入れる

1. iPad（または送迎表を作るパソコン）で、アプリを開きます。
2. 「設定」を押します。
3. 次を入れて「この端末に保存する」を押します。

| らん | 入れるもの（例） |
|---|---|
| リポジトリ名 | `あなたのアカウント名/soutai-data` |
| ブランチ | `main` |
| アクセストークン | さきほどコピーした `github_pat_...` |
| あなたのお名前 | `田中`（だれが保存したかの記録用） |
| 事業所 | 生活介護 八幡 |

4. 「つながるか試す」を押して、緑の帯で「つながりました」と出るか確かめます。
5. 画面の上の札が「**GitHubに保存します**」に変われば、本番の状態です。

### 鍵のあつかい（かならず守ってください）

- **共用のタブレットには入れないでください。** 送迎表を作る人の端末だけに入れます。
- 他の人に見せない・送らない・写真に撮らない。
- 漏れたかもしれないときは、GitHub の Fine-grained tokens の画面でその鍵を **Revoke（失効）**させ、
  新しく作り直します。アプリの設定で「この端末からトークンを消す」も押してください。
- 期限（Expiration）が切れると保存できなくなります。そのときは新しい鍵を作って、設定に入れなおします。

# 3. LINE WORKS 配信のしたく（画像をトークに送る）

「確定して配信」を使うときだけ必要なしたくです。**印刷だけで使うなら、ここは飛ばしても大丈夫です。**
ヒヤリハットで使っている LINE WORKS の Bot を、そのまま使いまわします。

## 3-1. 何が起きるのか（しくみ）

1. 職員が「**確定して配信**」を押します。
2. アプリが、その週の送迎表を保存し、つづけて
   `publish-requests/yahata-2026-08-03.json` という**小さな「配信してください」の紙**を
   データ用リポジトリに置きます（だれが・いつ・どこの・どの週かが書いてあります）。
3. それが合図になって、GitHub の中の**お手伝いさん（GitHub Actions）**が動きます。
4. お手伝いさんが、印刷とまったく同じ紙面を組み立て、**PNG画像**にします。
5. その画像を **LINE WORKS の Bot** から管理グループのトークへ送ります。
6. 送り終わったら、さっきの「配信してください」の紙を `publish-requests/done/` に片づけます。
   （同じ依頼で何度も送らないようにするためです）

押してからトークに届くまで、だいたい **1〜2分**です。

## 3-2. LINE WORKS の情報を集める（6つ）

<https://developers.worksmobile.com/> に、LINE WORKS の管理者アカウントでログインします。

### Client ID / Client Secret / Service Account / Private Key

1. 上の「**Developer Console**」→ 左の「**API**」→「**ClientApp**」を開きます。
2. ヒヤリハットで使っているアプリの名前をクリックします（新しく作らないでください）。
3. その画面に次の3つが並んでいます。
   - **Client ID** … 短い英数字の文字列
   - **Client Secret** … 「表示」を押すと見えます
   - **Service Account** … `〜.serviceaccount@ドメイン` という形のもの
4. **Private Key（秘密鍵）** は、同じ画面の Service Account のところにある
   「**Private Key 発行**（または再発行）」から `.key` ファイルとしてダウンロードします。
   - すでにヒヤリハットで使っている鍵ファイルが手元にあるなら、それを使ってください。
   - **再発行すると、前の鍵は使えなくなります。**
     ヒヤリハットの方も同じ鍵を使っているときは、再発行するとヒヤリハットが止まります。
     手元の鍵ファイルが見つからないときだけ再発行し、ヒヤリハット側も新しい鍵に入れかえてください。

### Bot ID

1. 同じ Developer Console の 左の「**Bot**」を開きます。
2. ヒヤリハットで使っている Bot をクリックすると、**Bot ID**（`2000001` のような数字）が出ています。

### チャンネルID（どのトークに送るか）

1. LINE WORKS のトークで、**送迎表を届けたい管理グループのトークルーム**を開きます。
2. そのトークルームに、上の Bot が**参加している**ことを確かめます（いなければ招待します）。
3. トークルームの右上のメニューから「**チャンネルID**」を開くと、
   `12345a12-b12c-12d3-e123fghijkl` のような文字が出ます。これをコピーします。

## 3-3. GitHub Secrets に登録する

集めた6つを、**データ用リポジトリ（`soutai-data`）**の金庫に入れます。
ここに入れた値は、あとから人が読むことはできません（GitHub の画面でも見えません）。

1. GitHub で `soutai-data` を開きます。
2. 上の「**Settings**」→ 左の「**Secrets and variables**」→「**Actions**」を開きます。
3. 緑の「**New repository secret**」を押し、下の表のとおりに1つずつ登録します。
   **Name はここに書いてあるとおり、大文字で正確に**入れてください。

| Name（そのまま入れる） | Secret（入れる値） | どこから持ってくるか |
|---|---|---|
| `LW_CLIENT_ID` | Client ID | Developer Console → API → ClientApp → アプリ |
| `LW_CLIENT_SECRET` | Client Secret | 同じ画面（「表示」を押す） |
| `LW_SERVICE_ACCOUNT` | `〜.serviceaccount@ドメイン` | 同じ画面 |
| `LW_PRIVATE_KEY` | 秘密鍵ファイルの**中身ぜんぶ** | ダウンロードした `.key` ファイルをメモ帳で開いてコピー |
| `LW_BOT_ID` | Bot ID（数字） | Developer Console → Bot |
| `LW_CHANNEL_ID` | チャンネルID | 送りたいトークルームのメニュー |

> **`LW_PRIVATE_KEY` のコツ**
> `-----BEGIN PRIVATE KEY-----` の行から `-----END PRIVATE KEY-----` の行まで、
> **改行もそのまま**、まるごと貼りつけます。前後に空白が入っても大丈夫です。
> （改行が `\n` という2文字になってしまっていても、アプリ側で直すようにしてあります）

## 3-4. 配信のしくみを、データ用リポジトリに置く

1. `C:\Users\tanak\Projects\soutai-app\data-repo-files\publish.yml` をメモ帳で開きます。
2. 中の **`repository: YOUR-ACCOUNT/soutai-app`** の1行を、
   ご自分のアカウント名に書きかえます（例：`repository: tanaka-hiroshima/soutai-app`）。
   **ここだけです。**
3. ファイルの中身を**ぜんぶコピー**します（Ctrl+A → Ctrl+C）。
4. GitHub で `soutai-data` を開き、「**Add file**」→「**Create new file**」を押します。
5. ファイル名のらんに、次を**そのまま**打ちます（`/` も含めて。打つと勝手にフォルダになります）。

   ```
   .github/workflows/publish.yml
   ```

6. 下の広いらんに、コピーした中身を貼りつけます（Ctrl+V）。
7. 「**Commit changes**」を押します。

> アプリ用リポジトリ（`soutai-app`）を **private** にした場合は、この方法では中を見られません。
> その場合は `soutai-app` を public にするか、詳しい人に相談してください。

## 3-5. ためしてみる

1. アプリで、どこかの週をぜんぶ埋めて「保存」します。
2. 「**確定して配信**」を押し、確認の画面で「配信する」を押します。
3. 「配信をお願いしました。1〜2分でトークに届きます」と出ます。
4. GitHub の `soutai-data` の上の「**Actions**」を開くと、動いているところが見られます。
   - 緑のチェック … うまくいきました。トークを見てください。
   - 赤いバツ … 失敗です。クリックすると**日本語で理由**が出ます。
     失敗した理由は `publish-requests/done/` のファイルにも残ります。

## 3-6. 秘密の値のあつかい

- Client Secret と秘密鍵は、**リポジトリの中のファイルには絶対に書かないでください**。
  必ず 3-3 の Secrets に入れます（このアプリのプログラムも、ログに出さないようにしてあります）。
- 送迎表の画像には利用者のお名前が入ります。
  そのため画像は**データ用リポジトリにも保存しません**（送るだけです）。
  うまくいかないときの確認用に、GitHub の Actions の中に7日間だけ残ります。

# 4. 使いかた

1. **週と曜日をえらぶ** … 上の ◀ ▶ で週、その隣で曜日をえらびます。
2. **「自動で割り当て」をおす** … その曜日に来る方が、定員と車椅子スペースを守って車に入ります。
   同じ地区の方はできるだけ同じ車になります。
3. **かえたい人を指でうごかす** … 名前のタイルを、入れたい席へひっぱります。
   - いっしょに乗れない組み合わせのときは、確認が出ます。**禁止はしません**（最後は職員の判断です）。
   - 車椅子スペースがいっぱいの車には入りません。
   - 「まだ乗っていない人」のらんへ戻すと、降ろせます。
   - 時刻は、動かすと先頭から7分きざみで入りなおします。手で直すこともできます。
4. **「送り」タブ** … はじめは「迎え」のコピーが入ります。ちがう人だけ直してください。
   「送り不要」の方は、はじめから入りません。
5. **当日変更** … 名前の右の「当日変更」を押すと、印刷したときその行が**赤字**になります。
6. **この日のメモ** … 画面のいちばん下です。引き継ぎ事項（ピンク）・外部の予定（青）・ふつうのメモを入れます。
   紙のいちばん下のらんに出ます。
7. **「保存」をおす** … GitHub に残ります。押すまでは残りません。
   押していないときは、上に「● まだ保存していません」とオレンジで出ます。
8. **「印刷」をおす** … 紙のかたちの画面になります。「印刷する」でA4たて1枚に出ます。
9. **「確定して配信」をおす** … 紙と同じ画像が、LINE WORKS の管理グループのトークに届きます。
   - まだ乗っていない人が**その週のどこかに**残っていると、教えて止まります。
     どの曜日のどちらの便が空いているか出るので、うめてから押しなおしてください。
   - 押すと確認の画面が出ます。「配信する」で、保存＋配信のお願いをします。
   - 届くまで**1〜2分**かかります。何度も押さないでください。
   - 同じ週をもう一度配信したいときは、直してから、また押せば新しい方が届きます。
   - したくがまだのときは「3. LINE WORKS 配信のしたく」を見てください。

## だれかと同時に直してしまったとき

このアプリは**1人が編集する**前提です。
それでも、ふたりが同じ週を直して保存すると、あとの人に
「**他の人が先に保存しました。画面を読み直してください**」と出ます。
このときは、先の人の内容が残っています。読み直して、必要なところをもう一度直してください。

# 6. 困ったとき

| こうなった | こうしてください |
|---|---|
| 画面が白いまま／車が出ない | ダブルクリックで開いていないか確認。`http://localhost:8080` から開きます |
| 「お試しモード」から変わらない | 設定でトークンとリポジトリ名の両方が入っているか確認します |
| 「トークンを確認してください」と出る | 期限切れか、権限が足りません。新しい鍵を作り直します（2-3） |
| 「他の人が先に保存しました」と出る | ほかの人が同じ週を保存しています。読み直してから直します |
| 「通信できませんでした」と出る | Wi-Fi につながっているか確認します |
| アプリがどうしても動かない | GitHub の `soutai-data` を開き、`data/事業所/plans/その週.json` を見れば、送迎表の中身は残っています |

## 配信（LINE WORKS）で困ったとき

まず `soutai-data` の「**Actions**」を開き、赤いバツが付いた行をクリックしてください。
**日本語で理由が出ます**。よくあるものは次のとおりです。

| Actions に出る文 | 意味と直しかた |
|---|---|
| `GitHub Secrets が足りません：…` | 3-3 の登録もれです。書いてある名前を登録します（名前は大文字で正確に） |
| `秘密鍵（LW_PRIVATE_KEY）の形が違います` | `-----BEGIN PRIVATE KEY-----` からの全体が入っていません。入れなおします |
| `HTTP 401`／`invalid_grant` | Client Secret か秘密鍵、Service Account がちがいます。3-2 を見直します |
| `HTTP 403` | Bot にトークへ送る権限がない、または Developer Console の Scope に `bot` がありません |
| `HTTP 404` | Bot ID かチャンネルIDがちがいます。または Bot がそのトークルームにいません |
| `〜の送迎表が見つかりません` | 配信の前に「保存」をしていません。保存してから、もう一度配信します |
| `Repository not found`（アプリの取り出しで失敗） | `publish.yml` の `repository:` の行が、ご自分のアカウント名になっていません（3-4） |
| 何も起きない（Actions が動かない） | `.github/workflows/publish.yml` の場所か名前がちがいます。作りなおします（3-4） |
| トークの画像の文字が □ になる | 日本語フォントを入れる手順が抜けています。`publish.yml` を貼りなおします |

うまくいかないあいだも、**印刷は使えます**。急ぐときは印刷して、配信はあとから直してください。
