# データ構造

送迎表のデータは、ぜんぶ**人が読める JSON の文字ファイル**です。
データ用リポジトリ（`soutai-data`、private）に、次のように置きます。

```
data/
├── facilities.json                     事業所の一覧（4施設ぶん）
├── yahata/                             事業所ごとにフォルダを分ける
│   ├── users.json                      利用者マスタ
│   ├── vans.json                       車両マスタ
│   ├── ng-pairs.json                   同乗NGペア
│   ├── drivers.json                    運転手（紙のバッジの色）
│   └── plans/
│       ├── 2026-08-03.json             1週間分の送迎表（週はじまりの月曜日がファイル名）
│       └── 2026-08-10.json
├── yahatagaoka/                        （八幡ヶ丘。まだ作っていない）
├── toshimatsu/                         （利松）
└── misuzuen/                           （美鈴園）

publish-requests/                       配信の依頼（LINE WORKS へ送る合図）
├── yahata-2026-08-03.json              「この週を配信してください」
└── done/                               送り終わったもの（結果つき）
    └── yahata-2026-08-03-20260729T093512.json
```

- **事業所ごとにファイルを分けています。** 八幡を直しても、ほかの事業所には影響しません。
- **週ごとにファイルを分けています。** 先週の表を触らずに、今週だけを直せます。
- ファイルが無いときは「まだ作っていない」あつかいになり、画面はこわれません。
  マスタ編集や保存をすると、そのときに新しく作られます。
- どのファイルにも `schemaVersion`（かたちの版）が入っています。
  あとから項目を増やしても、古いファイルが読めるようにするための番号です。
- 項目が足りないファイルを読んでも、アプリが既定値でおぎないます。
  **知らない項目は消さずに残します**ので、手で書き足したメモも失われません。

## facilities.json（事業所）

```json
{
  "schemaVersion": 1,
  "facilities": [
    {
      "id": "yahata",
      "name": "生活介護 八幡",
      "shortName": "八幡",
      "company": "株式会社障がい者ライフサポート",
      "address": "広島市佐伯区",
      "printTitle": "ファニー送迎表",
      "days": [1, 2, 3, 4, 5, 6],
      "startTimes": { "out": "08:20", "ret": "15:30" },
      "stepMinutes": 7,
      "areas": { "佐伯区": "#7faad5", "西区": "#e084b3" }
    }
  ]
}
```

| 項目 | 意味 | 例 |
|---|---|---|
| `id` | 事業所の記号。フォルダ名になります。**あとから変えないでください** | `yahata` |
| `name` | 画面に出す名前 | `生活介護 八幡` |
| `shortName` | 保存の履歴（コミットメッセージ）に使う短い名前 | `八幡` |
| `company` | 紙の左上と下に出る会社名 | `株式会社障がい者ライフサポート` |
| `address` | 紙の左上の小さい字 | `広島市佐伯区` |
| `printTitle` | 紙の見出し | `ファニー送迎表` |
| `days` | 送迎をする曜日。**1=月、2=火、…、6=土** | `[1,2,3,4,5,6]` |
| `startTimes.out` | 迎えの1人目の時刻 | `08:20` |
| `startTimes.ret` | 送りの1人目の時刻 | `15:30` |
| `stepMinutes` | 次の人まで何分あけるか | `7` |
| `areas` | エリアの名前と色。画面のタイルの左の色になります | `{"西区":"#e084b3"}` |

> `areas` に無いエリア名を利用者に付けると、タイルの色が灰色になります。
> エリアを増やしたときは、ここにも色を足してください。

## users.json（利用者マスタ）

```json
{
  "schemaVersion": 1,
  "facilityId": "yahata",
  "updatedAt": "2026-07-29T00:00:00.000Z",
  "users": [
    {
      "id": "u01",
      "name": "井上 健太",
      "area": "佐伯区",
      "wheelchair": false,
      "days": [1, 2, 3, 4, 5, 6],
      "noReturn": false,
      "note": "",
      "active": true
    }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `id` | 利用者の記号。**変えないでください**（過去の送迎表がこの記号で人を覚えています） |
| `name` | お名前。紙にもこのまま出ます |
| `area` | エリア（地区）。自動割り当てでまとめる目印。タイルの色にもなります |
| `wheelchair` | 車椅子の方なら `true`。車椅子スペースの数で判定します |
| `days` | 来られる曜日（1=月 … 6=土）。ここに無い曜日には出てきません |
| `noReturn` | 送りが要らない方（ご家族のお迎えなど）なら `true`。**送りの画面に出ません** |
| `note` | 覚え書き。画面や紙には出しません |
| `active` | `false` にすると、記録は残したまま送迎表に出なくなります（退所された方など） |

## vans.json（車両マスタ）

```json
{
  "schemaVersion": 1,
  "vans": [
    {
      "id": "v1",
      "name": "ハイエース",
      "seats": 6,
      "wheelchairSeats": 1,
      "driver": "山田",
      "days": [1, 2, 3, 4, 5, 6],
      "note": "",
      "active": true
    }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `id` | 車の記号。**変えないでください** |
| `name` | 車の名前。紙では左端にたて書きで出ます |
| `seats` | ふつうの座席の数 |
| `wheelchairSeats` | 車椅子のままで乗れる数 |
| `driver` | いつもの運転手。その日に変えたいときは送迎表側で指定します |
| `days` | その車が走る曜日。**土曜だけ台数を減らす**ときはここで外します |
| `note` | 紙の車名の下に出る小さい字。空なら「○名」（＝定員）が出ます |
| `active` | `false` にすると使わない車になります |

**乗れる人数（定員）＝ `seats` ＋ `wheelchairSeats`** です。
画面の座席の行数もこの数になります。

## ng-pairs.json（同乗NGペア）

```json
{
  "schemaVersion": 1,
  "pairs": [
    { "a": "u01", "b": "u03", "reason": "車内で言い合いになることがある" }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `a` / `b` | いっしょに乗せない2人の利用者の `id` |
| `reason` | そのわけ。画面の確認には出しませんが、あとで見返すために書いておきます |

- 自動割り当ては、このペアが同じ車にならないようにします。
- 手でうごかしたときは**確認を出すだけで、禁止はしません**。
  「職員の配置によっては大丈夫」という現場の判断を残すためです。

## drivers.json（運転手）

紙の運転手バッジの色と1文字を決めるためのファイルです。

```json
{
  "schemaVersion": 1,
  "drivers": [
    { "id": "d1", "name": "田中父", "initial": "田", "color": "green" }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `name` | お名前。車両マスタの `driver` と同じ字にしてください |
| `initial` | バッジの丸の中に出る1文字 |
| `color` | `green` / `blue` / `orange` / `pink` / `purple` / `teal` のどれか |

ここに載っていない運転手は、紙では灰色のバッジになります。

## plans/2026-08-03.json（週次プラン）

1週間分の送迎表です。**ファイル名は、その週の月曜日**です（日曜日は前の週にふくめます）。

```json
{
  "schemaVersion": 1,
  "facilityId": "yahata",
  "weekStart": "2026-08-03",
  "updatedAt": "2026-07-29T08:57:34.145Z",
  "updatedBy": "田中",
  "days": {
    "1": {
      "out": {
        "vans": {
          "v1": {
            "driver": null,
            "memo": "雨の日は玄関前まで",
            "rows": [
              { "userId": "u17", "time": "08:20", "changed": true },
              { "userId": "u03", "time": "08:27", "changed": false },
              { "userId": null, "time": "", "changed": false }
            ]
          }
        }
      },
      "ret": { "vans": { "v1": { "driver": "", "memo": "", "rows": [] } } },
      "notes": [
        { "kind": "hand", "text": "岡田様 車椅子 引き渡し" },
        { "kind": "ext", "text": "健康クリーニング" },
        { "kind": "plain", "text": "高木様 迎え無し" }
      ]
    }
  }
}
```

### いちばん外側

| 項目 | 意味 |
|---|---|
| `weekStart` | その週の月曜日（`2026-08-03`）。ファイル名と同じ |
| `updatedAt` | 最後に保存した日時（コンピュータの書き方） |
| `updatedBy` | 最後に保存した人。設定の「あなたのお名前」が入ります |
| `days` | 曜日番号（`"1"`=月 … `"6"`=土）ごとの中身 |

### 曜日の中身（`days["1"]`）

| 項目 | 意味 |
|---|---|
| `out` | **迎え**（往路） |
| `ret` | **送り**（復路） |
| `notes` | その日のメモ。**紙のいちばん下の1行**に出ます |

### 車ごとの中身（`out.vans["v1"]`）

| 項目 | 意味 |
|---|---|
| `driver` | **その日その便の運転手**。`null` なら車両マスタの運転手、`""`（空）なら紙に「？未定」と出ます |
| `memo` | 車ごとのメモ（画面の車のカードの下のらん）。紙では日ごとのメモ欄に「車名：〜」として出ます |
| `rows` | 座席の並び。**定員と同じ数**あります。前から順に乗車順です |

### 座席1つ（`rows[0]`）

| 項目 | 意味 |
|---|---|
| `userId` | 乗る方の `id`。空席は `null` |
| `time` | その方の時刻。先頭から `stepMinutes`（7分）きざみで入りますが、手で直せます |
| `changed` | `true` にすると、**紙でその行が赤字**になります（当日の変更） |

### メモ（`notes`）

| `kind` | 紙での見た目 | 使いかた |
|---|---|---|
| `hand` | **ピンクの帯** | 引き継ぎ事項（例：谷口様 車椅子 引き渡し） |
| `ext` | **青い帯** | 外部の予定（例：健康クリーニング、行動援護） |
| `plain` | 「・」つきの文字 | ふつうのメモ（例：丸本様 迎え無し） |

この色分けは、ヒヤリハット報告など社内の他の書類とそろえています。

## 読みこむときの決まり（安全のため）

手で直したファイルや、古い形のファイルを読んでも画面が壊れないように、次のように整えます。

| こういうとき | こうなります |
|---|---|
| 曜日・迎え／送り・車のわくが足りない | からのわくを作って足します |
| 車の定員を減らした | 乗っている方を前へ詰めて、あふれた方は「まだ乗っていない人」に戻ります |
| 同じ方が2つの車に入っている | 先に見つかった1つだけ残します |
| その曜日に走らない車のデータがある | 消さずに残しますが、画面には出しません |
| 古い項目名（`wc`・`uid`）で書かれている | 新しい項目名（`wheelchair`・`userId`）として読みます |
| メモが文字列だけ、または `{"chip":"…"}` の形 | `{"kind":"plain","text":"…"}` の形にそろえます |
| 利用者マスタに無い `userId` が入っている | 紙には「（マスタに無い方）」と出ます。マスタを直してください |

## publish-requests/（配信の依頼）

「確定して配信」を押すと、アプリがこのファイルを1つ置きます。
**送迎表そのものではなく、「送ってください」という合図の紙**です。
これが増えたことをきっかけに、GitHub Actions が画像を作って LINE WORKS へ送ります。

`publish-requests/yahata-2026-08-03.json`

```json
{
  "schemaVersion": 1,
  "facilityId": "yahata",
  "facilityName": "生活介護 八幡",
  "weekStart": "2026-08-03",
  "requestedBy": "田中",
  "requestedAt": "2026-07-29T09:35:00.000Z",
  "status": "pending",
  "message": "送迎表ができました\n生活介護 八幡　8/3(月)〜8/8(土)\n（田中 が確定しました）\n当日の変更は、必ず事務所へご連絡ください。",
  "results": []
}
```

| 項目 | 意味 |
|---|---|
| `facilityId` / `facilityName` | どの事業所の送迎表か |
| `weekStart` | どの週か（週はじまりの月曜日） |
| `requestedBy` | だれが押したか（設定画面の「あなたのお名前」） |
| `requestedAt` | 押した時刻 |
| `status` | `pending`（お願いした）→ `done`（送れた）／`failed`（送れなかった） |
| `message` | トークに出す本文。ここを手で直せば、届く文も変わります |
| `results` | 送った結果の記録（何度か試したときは増えていきます） |

送り終わると、このファイルは結果を書き足して `publish-requests/done/` に移されます。

```json
  "status": "failed",
  "results": [
    { "at": "2026-07-29T09:36:10.000Z", "ok": false, "detail": "GitHub Secrets が足りません：LW_BOT_ID（Bot ID）", "imageBytes": 0 }
  ]
```

- `done/` に移すのは、**同じ依頼で何度も配信してしまわないため**です。
  （Actions は `publish-requests/` の直下のファイルだけを合図にしています）
- 失敗したときも `done/` に移り、`detail` に日本語で理由が残ります。
  直したら、アプリでもう一度「確定して配信」を押してください。
- このフォルダに**利用者のお名前は入りません**（画像もここには残しません）。

## 保存のしかた（上書き事故を防ぐ）

GitHub からファイルを読むとき、そのファイルの版番号（`sha`）もいっしょに受け取ります。
保存するときはその版番号を送り、**その間にだれかが保存していたら GitHub が断ります**。
そのときアプリは「他の人が先に保存しました。画面を読み直してください」と出し、
先に保存された内容を守ります。
