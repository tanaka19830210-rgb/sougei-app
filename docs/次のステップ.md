## 1. 今回の範囲から外したもの（やらないと決めたもの）

### LINE WORKS への配信
確定した送迎表を、管理グループへ自動で送るしくみです。
今回は入れていません。印刷ボタンから紙に出すところまでです。

- ブラウザから LINE WORKS の API を直接呼ぶと、**Bot の鍵をブラウザに置くことになる**ため危険です。
  ヒヤリハット報告の自動化と同じように、**サーバ側（GAS など）で送る**のが順当です。
- 進めかたの案：データ用リポジトリの週次プラン JSON を GAS が読み、
  Flex メッセージを組んで配信する（アプリ側は何も変えなくて済みます）。

### PDF の自動生成
今回は「印刷画面 →（ブラウザの印刷）→ PDF として保存」で代わりにしています。
自動で PDF ファイルを作って残す／送るのは、上の配信とセットで考えるのが良いと思います。

### 顔写真つきのカード
同意を取るなどの手間が大きいため、今回も名前とエリア色のタイルのままです。

### 乗車順（ルート）の最適化
決定どおり、持っていません。並び順は職員が手で入れかえます。
時刻は先頭から7分きざみで入りますが、手で直せます。

### 複数人での同時編集
「1人が編集する」前提です。ただし、うっかり2人で保存したときに古い内容で上書きしないよう、
**「他の人が先に保存しました」と出して止める**しくみだけは入れました。

## 3. 動かしてみて決めたいこと（試験運用の観察ポイント）

引き継ぎ書のとおり、まず**八幡で4週間**試してから他事業所へ広げる想定です。
そのとき次を見てほしいです。

1. **自動割り当ての結果が、実際の運用に近いか。**
   いまは「車椅子の方を先に、あとは同じエリアの人が乗っている車へ」という考えかたです。
   実際は「この方はこの車」という決まりごとがあるかもしれません。
   あるなら、利用者マスタに「いつもの車」を足すのが早いです。
2. **7分きざみが実態に合っているか。** 合わないなら事業所ごとの設定を変えます。
3. **タイルの大きさ・指でのつかみやすさ。** iPad の実機でしか分かりません。
4. **メモの入れかた。** 車ごとのメモと日ごとのメモ、両方を使うか、どちらかで足りるか。
5. **1週間ぶんを作るのに何分かかるか。** 手作業と比べてどれだけ楽になったか。
